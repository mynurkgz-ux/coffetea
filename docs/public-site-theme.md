# Настройка главной страницы

Это одно кафе и один общий каталог. Тему и товары сайта может менять только назначенный главный администратор.

## Назначить главного администратора

1. Разверните актуальные правила Firestore:

   ```powershell
   firebase deploy --only firestore:rules --project cfteasite
   ```

2. В Firebase Console откройте **Authentication → Users** и скопируйте UID аккаунта, которому нужно дать доступ.
3. Для глобального администратора создайте в **Firestore Database → Data → admin** документ с ID, равным UID аккаунта, и полем `role` (string) со значением `admin`. Либо для аккаунта Coffetea с обычным профилем добавьте в `profiles/{UID}` поле `siteAdmin` (boolean) со значением `true`.
4. Откройте приложение под этим аккаунтом. В разделе **Баннеры** можно добавлять, сортировать, скрывать и редактировать баннеры автоматической карусели на главной. В разделе **Товары** можно управлять меню; товары со скидкой по очереди показываются в промо-карточке. В разделе **Отзывы** администратор проверяет и публикует отзывы покупателей. В разделе **Настройки** можно изменить цветовую тему сайта и выбрать фоновую анимацию: «Плавающий», «Газировка», «Пульс», «Звёздный хлопок», «Снегопад» или «Без анимации». Анимация показывается как в hero-блоке, так и на светлых секциях главной страницы.

Снять доступ глобального администратора можно, удалив его документ из коллекции `admin`; для обычного профиля удалите `siteAdmin` или установите `false`.

Цветовая тема и режим анимации хранятся в `siteSettings/publicHome`. Единый каталог хранится в `siteProducts` и отображается на главной странице и `/catalog`. Старые товары в `venues/{venueId}/products` не смешиваются с этим каталогом.

Авторизованный покупатель оформляет всю корзину одним заказом в `siteOrders`; оплата производится наличными на кассе при получении. Администратор видит заказы в одном окне **Заказы** и меняет статусы: новый, готовится, готов к выдаче, выдан или отменён. При отметке «Выдан» наличная оплата фиксируется как полученная. Покупатель видит статусы своих заказов в каталоге. После изменения правил Firestore опубликуйте их в проекте Firebase, чтобы создание заказов, чтение истории покупателя и обновление статусов работали.

Самостоятельная регистрация покупателя создаёт личный профиль в `profiles/{UID}` с ФИО и почтой и переводит его в `/account`. Личный кабинет показывает данные аккаунта и только заказы текущего покупателя; `/buyer` перенаправляет в `/account`. Для новых buyer-профилей нужно опубликовать актуальные правила Firestore. Если аккаунт Firebase успел создаться, а профиль — нет, войдите по Gmail ещё раз и завершите создание профиля в появившейся форме. При отказе Firestore сначала опубликуйте актуальные правила и повторите попытку.

Для входа покупатели используют уникальный логин `userb` с цифрами, который показывается в личном кабинете; администратор сайта входит по `admin`. Администраторы кафе получают уникальный логин `admin` с цифрами. Новые аккаунты получают такой логин при регистрации, а старые аккаунты переходят на него после первого входа по Gmail и паролю. Gmail остаётся в профиле покупателя как контакт. Для обновления логина старого профиля нужно опубликовать актуальные правила Firestore.

Отзывы покупателей записываются в `siteReviews` со статусом `pending`; только отзывы со статусом `approved` показываются публично. Баннеры хранятся в `siteBanners`, публично показываются только документы с `active: true`. Для запуска опубликуйте актуальные правила Firestore.
